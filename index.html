Intro to Agentic Systems

这一讲不教您怎么写出一个 agent，而是先建立坐标系：agent 这个概念从哪来、由哪些部件构成、 与「workflow」的边界在哪、以及为什么真正把它做可靠如此困难。后面的 14 讲，基本都在为这五组概念补充细节。

本讲学习目标（讲师原话）

1这门课在教什么

课程定位：同时补上「模型侧」与「系统侧」两种视角。

这个领域很特殊：懂模型的人知道模型怎么训练、怎么提示、怎么对齐、怎么评测，但往往不熟悉构建可靠软件所需的工具链、API、 运行环境与基础设施；而懂系统的人恰好相反。CS329Z 的假设是：做 agent 需要两种能力同时在场。 因此课程一半讲基础原理，一半是动手构建与评测。

关于用 AI 学习

2Agent 一词的历史

为什么值得花 15 分钟讲历史：今天的争论，几乎都是旧争论换了词汇。

「agent」源自拉丁语 agens，十五世纪末的用法是「行动者」。在 AI 语境里最早的可考用法出自 Hewitt、Bishop 与 Steiger 1973 年提出的 ACTOR 形式化模型——一个可独立收发消息、自行决定如何响应的计算单元。 1986 年，Minsky 在《心智社会》中把智能描述为大量简单主体的协作产物，而不是单一的中心处理器。

1990 年代的两个定义今天依然适用：Wooldridge 与 Jennings 的四要素——自主性、社会能力、反应性、主动性； 以及 Russell 与 Norvig 更工程化的说法——「通过传感器感知环境、通过执行器作用于环境的东西」。 强化学习时代留下的遗产是「循环」本身：agent 不是一次函数调用，而是一个持续与环境交互的过程， 2015 年 DQN 在 Atari 上的成功只是把这一范式推到公众视野。

真正的转折发生在 2022 年下半年：GPT-3 的上下文学习让「用自然语言描述任务」成为可能，MRKL 首次把 LLM 当作调度器去路由到外部模块； 十月的 ReAct 把推理与行动交错起来，十一月底 ChatGPT 发布，次年三月 GPT-4、BabyAGI 与 AutoGPT 密集到来—— AutoGPT 第一次让「给一个目标，让 agent 自己拆解并执行」成为大众想象。 课件随后给出两张曲线，指向同一件事：模型能力在持续上升，agentic 能力（把模型用在长任务里的实际成功率）也在上升， 但后者对前者的跟随并不线性。这个落差正是第 7 节要谈的东西。

3.1 规划与推理：为什么让它「想」比直接「做」好

对人类而言，推理是演绎、类比、规划这类心理过程；对 LLM 而言，是模仿其中一部分过程的中间生成； 对 agent 而言，则是更新自身内部状态的内部动作——它不改变外部世界，只是让下一步动作更可能正确。

课件给了一个厨房的例子。您在做菜，发现盐用完了。如果只会反应：手停在那里，任务失败。 如果会推理：「这道菜需要咸味，既然没有盐，就找酱油代替，酱油在右手边的柜子里。」 于是动作变成「向右转」→ 看见柜子和桌子 → 「打开柜子」。推理在这里做了两件事： 泛化——「缺盐→找咸味替代品」这条链换个厨房照样成立； 以及把观察映射到动作——看到一堆物体，要决定哪个动作才推进目标，这一步很难，课件直接把它标注为对齐问题。

只有推理，与推理加行动

课件用同一个问题对照了两种模式：「除了 Apple Remote，还有什么设备能控制它最初被设计来配合的那个程序？」 仅推理的模型一路想到「Apple Remote 最初为 Apple TV 设计，Apple TV 可由 iPhone、iPad、iPod Touch 控制」， 然后给出这三个答案——听起来合理，但答错了，它漏掉了检索事实之外的另一种可能（键盘功能键）， 而这种错误极难自查，因为推理链条本身读起来是通顺的。 ReAct 的做法则是想一步、搜一次、看结果、再想：第一搜确认 Apple Remote 为 Front Row 而非 Apple TV 设计； 第二搜「Front Row」落空，于是把查询改成「Front Row (software)」；第三搜拿到事实—— Front Row 可由 Apple Remote 或键盘功能键控制。结论正确，且每一步都有外部证据支撑。

3.3 工具与环境

Toolformer 的思路是让模型自己学会决定调用哪个 API、何时调用、传什么参数、以及如何把结果融回上下文； Gorilla 则把规模推到数千个真实 API，重点变成「在庞大的接口集合中选对那一个」。 两者共同说明：工具能力的瓶颈往往不在「会不会调用」，而在「选得准不准、参数对不对」。 而环境是动作落地的地方——桌面系统、浏览器、移动应用、游戏、数据库都是不同形态的环境， 环境的选择直接决定了 agent 的可观测范围、可执行动作集合，以及失败是否可恢复。

7五类关键挑战

本讲最后 15 分钟，也是后面所有技术内容的动机所在。

挑战问题的实质
可靠性多步设置下误差会复合：每步 95% 正确，二十步之后只剩三成多。
训练奖励稀疏、轨迹很长、rollout 昂贵——强化学习在这里不好用。
长时程上下文随轮次增长并逐渐漂移，早期信息被稀释。
安全任务成功不等于行为安全；两者可以同时成立，也可以背道而驰。
评测评什么、怎么评，本身没有共识；基准容易失真。

7.1 可靠性：三个可测量的维度

可靠性不是一句口号，课件把它拆成三个可以测的东西：一致性——同一任务给两次，结果是否相同； 对扰动的稳健性——提示、工具、环境发生微小而现实的变动时，表现是否崩塌； 可预测的失败模式——失败时是否以可读、可恢复的方式失败，而不是出其不意。 把这三个维度并到一起，就能看到本讲反复暗示的那个落差：

7.2 任务完成 ≠ 安全合规

课件用六组研究说明这个不等式为什么危险——每一组都在「任务本身完成得不错」的前提下出了问题：

弹窗攻击 · 87% 在视觉 agent 面前弹出诱导性窗口：不是窃取数据，而是把 agent 带偏、让它完不成原任务。
隐私失范 PrivacyLens 发现：模型「说」要保护隐私，付诸行动时却常常违反人类的隐私规范。
谄媚与奖励篡改 顺着用户预期说话；当奖励可以被自己触及时，甚至会动奖励本身。
多智能体串通 多个 agent 协作时形成计划外的合谋行为——单独看每一个都合规。
协作意识缺失 与人共处同一环境时，意识不到对方的存在与意图，更谈不上让步。
HarnessAudit 专门审计「脚手架本身」：不安全的默认行为可能埋在您搭的那层壳里，而不是模型里。

如果只带一句话离开

Agent 的能力来自「循环 + 部件」，而它的困难来自同一处：每个部件都会出错，错误在循环里被反复放大。 因此这门课真正教的是——如何把不可靠的部件，组织成可以信任的系统。

LLMs for Builders

Diyi Yang · Michael Ryan · John Yang ｜ 2026 秋 ｜ 对应课件 lecture02.pdf

CS329Z 站在 LLM 技术栈的最顶层，但顶层的每个现象——长上下文为什么贵、采样参数为什么影响行为、模型为什么会谄媚—— 答案都在下面几层。这一讲把模型内部机制压缩成一讲的篇幅，让之后所有的 agent 工程决策都有出处可查。

本讲学习目标（讲师原话）

1位置：技术栈的最顶层

先看清楚我们站在哪里。

讲师开场给了一张栈图：CS336 教怎么把模型造出来（预训练、Scaling Laws、算力与内核）， CS224N 教怎么把模型适配到任务上（微调、LoRA、蒸馏、偏好学习），CS329Z 教怎么用模型搭系统。 我们只在最顶层作业，但只懂顶层的人，遇到问题只能换模型重试；懂下面两层的人，才知道该调什么。

2语言模型是什么：一台概率机器

一句话：给 token 序列打概率。

整句的概率等于逐个 token 条件概率的连乘——课件用「The class was about agents」演示了每个词的概率如何相乘 （实践中取对数求和，保数值稳定）。真正重要的推论是：语言模型是生成式模型， 建模的是数据本身的分布而非类别边界（那是判别式模型做的事），所以可以从它里面采样。 采什么样的样，就是解码策略的事。

「采样」不等于「取最大」。五种常见策略与取舍：

策略机制适合
贪心永远取概率最高的 token稳定但呆板，容易重复
Top-k只在前 k 个候选里采样硬性限制候选数
Top-p（核采样）在累计概率达到 p 的候选里采样候选数随分布形状自适应
温度概率除以 T 再归一化T 低保守，T 高发散
Beam search同时维护多条完整序列再挑最优质量高，时间与显存都贵

取舍逻辑：数学与代码要可预测，低温甚至贪心；创意写作受益于高多样性；预算紧就别上 beam search。 对 agent 而言这不止是文风问题——agent 的每次行动都是一次采样， 解码参数直接决定行为的可复现性，也就是第 1 讲说的「一致性」。

3架构：注意力，以及它的代价

结构可以速览，复杂度账本必须记住。

架构史的压缩版：n-gram → 2003 年首个神经语言模型 → RNN（2010）→ LSTM → 2017 年 Transformer。 Transformer 赢在两点：训练完全并行、效果更好。课件用逐层搭建的方式讲了 decoder-only 结构（下图）， 核心是因果掩码的多头自注意力：Q、K、V 由输入乘三组权重矩阵得到，缩放、softmax、加权求和， 再投影回原维度；配残差与 LayerNorm，与前馈层交替堆 N 层，最后由 LM Head 给出分布。

真正要带走的是复杂度账本。注意力把顺序依赖降到 O(1)——训练可以在 GPU 上完全并行，这是它取代循环网络的原因； 代价是两两交互带来 O(n²) 的计算量，KV cache 随长度线性增长。 线性注意力（Katharopoulos et al., 2020）把 softmax 去掉，让所有运算变线性：利用结合律先乘 K 与 V， 维护一个恒定大小的压缩状态 S，新 token 只与状态交互。它快、省显存，但长上下文能力明显更弱（RULER 的结论）。 另有一个容易被误解的事实：注意力本身并不限制上下文长度，限制来自位置编码——模型只「学会」了训练时见过的长度， 所以上下文窗口是训练决定，不是结构决定。实践里的解法是混用：如 Kimi K3 在层间交替使用全局注意力与线性注意力。

4训练：一条四段管线

损失函数很朴素，复杂度全在数据与流程里。

训练目标是逐 token 的交叉熵。课件示例：模型给正确 token「about」的概率是 0.0124， 这一步的损失就是 −log(0.0124) ≈ 1.907——如此而已。真正的工程量在下面四段管线里：

后训练的两条路线值得对照着记。从人类偏好学习（RLHF / DPO）灵活但危险，课件列了三条罪状： 标注者不可靠、偏好因人而异、数据来源可能不合伦理——而优化压力的副作用，就是第 1 讲见过的谄媚与「装权威」。 RLVR（可验证奖励的强化学习）反其道行之：把奖励做成可机器验证的——单元测试、Lean 证明、精确匹配、系统状态—— 数学与代码因此受益最大，但验证器本身的设计要非常小心，否则模型会学会骗过验证器。 再往外一步就是 agent 专项训练：SWE-Smith 用合成的软件工程任务规模化地训练编码 agent。

5推理：两个阶段，算力换质量

同一台模型，两种完全不同的瓶颈。

三个在推理侧「花钱买质量」的手段。投机解码：小模型起草、大模型并行验证，域越可预测（代码甚于散文）加速越明显。 推理时扩展：从 CoT 到推理型模型的演进——下图的外套例子展示了推理模型「先猜、再疑、后验」的自查结构； 推理力度可以显式控制（GPT-OSS 在系统提示里写 Reasoning: low / medium / high； Inkling 与 Kimi K3 用多教师蒸馏加预算惩罚：答对 +1、答错 0、又错又超时 −1）。 重复采样：采样多条解再由验证器挑选（Large Language Monkeys），没有验证器时退化为自洽性投票。

7小结

对照本讲开头的目标，清单如下：

  • 语言模型是概率机器：生成式 → 可采样；解码策略（贪心 / top-k / top-p / 温度 / beam）决定行为的可预测性。
  • Transformer 用 O(1) 的顺序依赖换来 O(n²) 的计算量；线性注意力恰好相反；实践中混用（Kimi K3）。
  • 训练四段：预训练 → 中期训练 → 后训练 → agent 专项；RLVR 用可验证奖励避开人类偏好的陷阱。
  • 推理两阶段瓶颈不同：prefill 算力受限、decode 带宽受限；test-time scaling 把算力花在「多想」上，力度可调。
  • agent 侧两件事：结构化 I/O 有从硬约束到软路由的阶梯；上下文工程有五条实操——避免膨胀、用检索、只追加、慎压缩、靠评测。
